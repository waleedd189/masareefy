# مصاريفي (Masareefy) 💳

تطبيق ويب لمتابعة **مصروفات بطاقات الفيزا وأرصدتها**، بيقرا **رسائل البنك** ويحوّلها لعمليات متسجلة تلقائياً، وبيربط كل رسالة بالبطاقة الصح من آخر 4 أرقام — حتى لو عندك أكتر من بطاقة.

> واجهة عربية بالكامل (RTL) · بياناتك محلية على السيرفر بتاعك · مبني على Next.js وقابل للتطوير.

## 🚀 التشغيل المحلي


## 📲 استقبال رسائل البنك تلقائياً

1. من صفحة **الإعدادات** → اعمل **مفتاح API** جديد.
2. نزّل تطبيق **SMS Forwarder** (أو MacroDroid / Tasker) على الأندرويد.
3. اعمل قاعدة: أي رسالة من المرسل `CIB` / `NBE` / `QNB` … تتبعت POST على:

```http
POST https://<your-domain>/api/ingest
Authorization: Bearer <api-token>
Content-Type: application/json

{
  "text": "%message%",
  "sender": "%from%",
  "receivedAt": "%time%"
}
```

الرد:

```json
{
  "ok": true,
  "count": 1,
  "results": [
    { "status": "PARSED", "transactionId": "…", "amount": 320.75, "last4": "4321" }
  ]
}
```

**حالات الرسالة:** `PARSED` اتسجلت تلقائياً · `NEEDS_REVIEW` محتاجة تأكيد · `UNMATCHED` مفيش بطاقة بالأرقام دي · `IGNORED` رسالة مش مالية (OTP/إعلان) · `DUPLICATE` مكررة.

> تقدر كمان تلصق الرسائل يدوياً من صفحة **رسائل البنك** (وتلصق أكتر من رسالة مرة واحدة، سيب سطر فاضي بينهم).

## 📱 التثبيت والعمل أوفلاين

1. افتح الموقع مرة واحدة بالإنترنت، ثم افتح صفحة **أوفلاين**.
2. Android/Chrome: القائمة ⋮ ← **تثبيت التطبيق** أو **إضافة إلى الشاشة الرئيسية**.
3. iPhone/Safari: **مشاركة** ← **إضافة إلى الشاشة الرئيسية**.
4. بدون إنترنت يمكنك إضافة بطاقة أو عملية يدوية أو رسالة بنك؛ تُحفظ في IndexedDB على الجهاز.
5. عند عودة الاتصال، تتم المزامنة تلقائيًا عبر `/api/offline` مع حماية من تكرار العناصر.

> لا تمسح بيانات المتصفح أو تحذف التطبيق وفيه عناصر معلّقة. الـPWA لا يستطيع قراءة SMS تلقائيًا بسبب قيود المتصفح؛ هذه الخطوة تحتاج تطبيق Android أصلي في المرحلة التالية.

## 🧠 إزاي المحلل شغّال؟

```
نص الرسالة
   ↓ تطبيع (أرقام عربية ← إنجليزية، طي الهمزات والتاء المربوطة، إزالة التشكيل)
   ↓ قواعد مخصّصة (Regex من قاعدة البيانات) — لو فيه تطابق
   ↓ استثناءات: كود تفعيل (OTP) · رسالة تسويقية (PROMO) · مرسل شخصي (رقم موبايل) · كشف حساب بلا عملية
   ↓ قوالب موثّقة لكل بنك (named-group regexes) ⇒ مستوى VERIFIED وثقة 0.95–1.0
   ↓ المفردات: كلمات مبنية + كلمات انت بتعلّمها (الأطول بيفوز، وIGNORE له الأولوية)
   ↓ استخراج عام: المبالغ + العملات، وتمييز "المبلغ" عن "الرصيد المتاح" و"الحد الائتماني" ⇒ GENERIC وثقة 0.8
   ↓ آخر 4 أرقام (ending 1234 / ****1234 / المنتهية بـ 1234)
   ↓ نوع العملية (شراء، سحب، سداد، استرداد، رسوم، تحويل، إيداع) + الاتجاه (خصم/إضافة)
   ↓ التاجر + التاريخ + العملة الأجنبية لو العملية خارجية
   ↓ درجة ثقة 0—1 + مستوى (VERIFIED / GENERIC) ⇒ محرّك السياسة يقرر: تسجيل آلي / مراجعة / تجاهل
```

**30 بنك ومحفظة معرّفة:** CIB · الأهلي المصري (NBE) · QNB الأهلي · بنك مصر · الإسكندرية · القاهرة · العربي الأفريقي · HSBC · ADIB · كريدي أجريكول · SAIB · NBK · ABK · Mashreq · فيصل الإسلامي · EGBANK · المصرف المتحد (UBank) · الإمارات دبي الوطني · الراجحي · الأهلي السعودي · إنستاباي · ميزة · فودافون كاش · أورانج كاش · اتصالات كاش · وي باي · فوري · ڤاليو (valU) — وأي مرسل تاني بيشتغل بالمحرّك العام.

**القوالب الموثّقة:** `src/lib/sms/templates.ts` فيه ~26 قالب بمجموعات مسماة (`amount`, `last4`, `merchant`, `balance`, `date`, `fee`) بالعربي والإنجليزي، وإصدار المحلل `PARSER_VERSION = 2` — أي رسالة بتتسجل بالقالب بتاعه بتاخد مستوى **VERIFIED**، وغير كده **GENERIC**.

جرّب بنفسك: `npm run parser:test` (28 عينة حقيقية: بنوك، محافظ، OTP، تسويق، مرسل شخصي، كشف حساب).

### إضافة بنك جديد

ضيف عنصر في `src/lib/sms/banks.ts`:

```ts
{
  key: "my_bank",
  nameAr: "بنكي",
  nameEn: "My Bank",
  country: "EG",
  currency: "EGP",
  senders: ["MYBANK"],
  keywords: ["my bank", "بنكي"],
}
```

ولو صيغة الرسالة غريبة، ضيف قاعدة Regex من **الإعدادات** بمجموعات مسماة:

```regex
(?<amount>[\d,.]+)\s*ج\.م.*?(?<last4>\d{4}).*?(?<merchant>[^,.]+)
```

## 🛡️ سياسة الرسائل والميزانيات

من **الإعدادات → سياسة الرسائل والميزانية** تتحكم في:

| الإعداد | التأثير |
|---|---|
| تتبّع الرسائل | لو مقفول: كل الرسائل تتحفظ للمراجعة من غير تسجيل |
| التسجيل الآلي (AUTO_POST) | يسجّل العملية لوحده لما الثقة ≥ الحد المحدد |
| إيقاف مؤقت | كل حاجة تروح للمراجعة (وضع الصيانة) |
| اشترط قالب موثّق | التسجيل الآلي فقط من قالب بنك مؤكد (VERIFIED) |
| مراجعة العملات الأجنبية | أي عملية بعملة غير الجنيه تحتاج موافقتك |
| أقصى مبلغ للتسجيل الآلي | أكبر من كده ⇒ مراجعة |
| أنواع تحتاج مراجعة | مثلًا: السحب والتحويل دائمًا بموافقتك |
| اتعلّم من موافقاتي | كل تأكيد بيقوّي ربط المرسل بالحساب والفئة |

وكل رسالة بتظهر عليها **أسباب القرار** كشرائح واضحة («قالب غير موثّق»، «مبلغ أعلى من الحد»، «مرسل غير مربوط»…).

الميزانيات: إجمالية للشهر + لكل فئة (والفئات ممكن تبقى فرعية تحت فئة أب)، وبتظهر في الرئيسية كـ burn-down مع المتبقي ويومك المسموح ووتيرتك الفعلية والمتوقع آخر الشهر.

## 💰 حساب الأرصدة

- **بطاقة ائتمان:** `currentBalance` = المستحق عليك، و`availableAmount` = الحد − المستحق.
- **خصم مباشر / مسبقة الدفع:** `currentBalance` = الرصيد الفعلي.
- لو رسالة البنك فيها "الرصيد المتاح"، بيتاخد كنقطة ارتكاز موثوقة وتتطبّق عليه العمليات الأحدث منها فقط — ده بيمنع انحراف الأرصدة لو رسالة ضاعت.

```
│  ├─ theme.ts             # 🎨 نظام السمات: متغيرات + تطبيق + سكريبت ما قبل الرسم
│  ├─ auth-token.ts        # تجزئة مفاتيح الـAPI (SHA-256)
│  ├─ fx.ts                # تحويل العملات حسب الأسعار المحفوظة
│  └─ format.ts            # تنسيق الأرقام والتواريخ بالعربي
└─ server/actions/         # Server Actions (CRUD)
```

**التقنيات:** Next.js 16 (App Router + Server Actions) · TypeScript · Tailwind CSS 4 · Drizzle ORM · libSQL/SQLite · Zod.

## ☁️ النشر

الكود مكتوب بحيث قاعدة البيانات تتبدل من سطر واحد:

- **Turso (موصى به مع Vercel):** غيّر `DATABASE_URL` لـ `libsql://...` وضيف `DATABASE_AUTH_TOKEN` — من غير أي تعديل في الكود.
- **PostgreSQL:** بدّل `drizzle-orm/libsql` بـ `drizzle-orm/node-postgres` في `src/db/client.ts` وغيّر `dialect` في `drizzle.config.ts`.

> ملاحظة أمان: التطبيق حالياً بدون تسجيل دخول (استخدام شخصي). قبل ما تنشره على الإنترنت، فعّل حماية (Basic Auth على مستوى الاستضافة أو أضف Auth.js) — والـ webhook محمي بمفتاح API.
